# UI polish 0.5.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship 0.5.0 — a filterable, lighter font picker, a centred background tool, and a bigger, animated-arrival brand mark — after releasing the current unreleased work as 0.4.0.

**Architecture:** Four independent, reversible UI changes plus a release step. No document-schema change, so the whole release is shippable from `develop` on its own. The font picker keeps its existing `fontSections` partition and gains a filter over it; the rail keeps its fixed 56 dp height and gains a centred content style; the splash asset is re-cropped in the icon generator and the animated `BrandLoader` takes over the launch once the theme is known.

**Tech Stack:** Expo SDK 57, React Native 0.86, react-native-reanimated 4.5, react-native-skia 2.6, expo-splash-screen, sharp (icons), zustand.

**Spec:** `docs/superpowers/specs/2026-10-04-ui-polish-0-5-design.md`

## Global Constraints

- **No document change.** `PROJECT_FILE_VERSION` stays `2`. Do not touch `project-schema.ts`, `design-file.ts` or the storage platform modules.
- **`scripts/check-fonts.mjs` and `scripts/check-font-pins.mjs` read `font-picker-sheet.tsx` as text and must keep passing with no edits to those scripts.** The tokens that must survive in the file, verbatim: `SPECIMENS: Record<FontScript`, `arabic: '`, `latin: '`, `SPECIMENS[family.script]`, `fontSections`, `f.script === script`, `(['arabic', 'latin'] as const)`, `fontSections.map`, `useFontPins`, `familyPinId`, `googlePinId`, `parseFontPinId`, `humanizeRemoteFontId`, `parseRemoteFontKey`, `t.editor.pinnedFonts`, `flexDirection: 'row'`, `paddingStart`, `pinnedCollapsed`, `t.editor.collapsePinned`, `t.editor.expandPinned`.
- `src/i18n/strings.ts` declares **no imports**; add each new key to the `Translation` interface and to both the `ar` and `en` objects.
- `contextRail.height` stays `CONTEXT_RAIL_HEIGHT` (56). The canvas must not reflow when the tool changes.
- `src/editor/shortcuts.ts` and `src/editor/help/catalog.ts` may declare only `import type`; do not add value imports to them.
- Verification commands: `node scripts/verify.mjs` (sixteen tasks, parallel) and the single check when it covers the change. Format with `yarn format:fix`; never `npx prettier@3`.
- Phase 0 and Task 4.2 touch `staging` and `main` and push tags. **Do not run them without an explicit go-ahead from the human partner for that specific phase.**
- **There is no test runner.** Where a step says "Verify", it means the check script named, or the platform observation named — not an assertion that a test suite will run.

## Review Focus

Five conditions the design implies but no check exercises. Each is pinned to a task below.

1. **A pinned family whose script the filter is hiding.** It must still appear in the Pinned block (the pinned section is outside the filter), so the family is reachable and appears exactly once — not zero times.
2. **A filter that leaves the visible section empty while the query matches.** With `latin` filtered and `noto` typed, the Latin section is empty; the "no results" text must still be driven by `matches.length === 0 && remoteFamilies.length === 0`, so it does not lie while the Google section has hits.
3. **The filter's default when the active family is remote.** `familyForVariant(value)` returns `undefined` for a `remote:<id>:<weight>` key, so the default must fall back to `arabic` rather than throwing or rendering an empty list.
4. **Reduce Motion at launch.** The cover must not hold a static frame for an extra delay, and the routes must still appear; the app must never be left on the cover.
5. **Dark-mode splash.** If `splash-icon-dark.png` is missing or the `dark.image` key is wrong, the black mark returns on `#111111` — verify both generated files exist and are non-empty.
