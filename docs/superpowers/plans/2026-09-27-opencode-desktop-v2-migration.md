# OpenCode Desktop-V2 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the OpenCode Desktop 2.0.18 (V2) install fully functional — every MCP server, plugin, skill, command, and memory block loading — and remove the redundant V1 CLI.

**Architecture:** OpenCode is client–server; Desktop bundles its own V2 server (`resources/opencode-cli.exe`) and shares the global config root with the CLI. Migration = back up → remove the V1 CLI safely → reshape config files from V1 shape to V2 shape → update/replace the plugin set → reconcile with the GitHub sync repo → verify on Desktop.

**Tech Stack:** OpenCode Desktop 2.0.18 (V2), Windows PowerShell, npm, git, opencode-synced (GitHub config sync).

**Spec:** This conversation; source of truth is the V2 docs:
- `https://opencode.ai/v2/docs/mcp-servers/` (mcp.servers, disabled, timeout, oauth)
- `https://opencode.ai/v2/docs/plugins/` (plugins key, ~/.config/opencode/plugins discovery)
- `https://opencode.ai/v2/docs/build/plugins/migrate-v1` (plugin API break)
- `https://opencode.ai/v2/docs/skills/`, `/commands/`, `/agents/` (discovery paths)
- `https://opencode.ai/v2/docs/cli/` (uninstall + shared service)

## Global Constraints

- Target runtime is **Desktop 2.0.18 (V2) only**. The npm CLI (`opencode-ai@1.18.23`) is removed.
- **Never run `opencode uninstall`** — it deletes shared global config/data/state. Remove the CLI with `npm uninstall -g opencode-ai`.
- Config root: `C:\Users\adelpro\.config\opencode`. Data root: `C:\Users\adelpro\.local\share\opencode`.
- **Do not commit secrets.** MCP credentials use `{env:VAR}` substitution, never inline values.
- V2 field names: plugin list is **`plugins`** (not `plugin`); MCP servers live under **`mcp.servers`** (not directly under `mcp`); MCP servers use **`disabled`** (not `enabled`); per-server `timeout` is an **object**, not a number.
- Every config edit must be mirrored into the sync repo `adelpro/my-opencode-config`, or the next pull reverts it.
- Back up before touching anything (Task 1). If a step fails, restore from the backup and stop.

## Review Focus

Inputs/conditions most likely to bite an operator, each pinned by a test in its task:

- **`opencode.jsonc` is regenerated by opencode-synced** — editing only the local file gets reverted on the next pull of `adelpro/my-opencode-config` (Task 6).
- **Numeric MCP `timeout: 60000`** is invalid in V2 and fails config validation; V2 wants `{ "startup": 60000 }` or nothing (Task 3).
- **Header-authenticated remote servers** (`context7`, `github`) attempt OAuth in V2 unless `"oauth": false` is set (Task 3).
- **A stale V1 background service** may still be registered after the CLI is removed and confuse Desktop (Tasks 2 and 7).
- **Provider credentials** migrated to V2's integration system may need a fresh `/connect` sign-in (Task 7).
- **Skill IDs are path-derived and case-sensitive** in V2, not the frontmatter `name` (Task 7).
- **Secrets already sit in synced files** — a Context7 API key in `opencode.json`/`opencode-synced.overrides.jsonc`, and a pasted GitHub PAT in `opencode-sync-state.json` (Task 8).
