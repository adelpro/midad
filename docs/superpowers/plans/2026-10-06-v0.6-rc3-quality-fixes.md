# v0.6.0-rc.3 Quality Fixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix five defects found while testing the v0.6.0-rc.2 internal build:
first-launch RTL never applies without a manual restart; the font-picker
filter captions and the editor tool-rail captions truncate; the icon picker
still lists icons it cannot import; and a few font specimens render wrong.

**Architecture:** RTL moves from a post-render `I18nManager.forceRTL` call,
which native platforms only honour on the next launch, to a one-shot cold-start
direction check that persists the choice and reloads the JS bundle when the
direction actually changes. Latin/Arabic captions move to a single
shrink-to-fit label so no surface can clip again. Icon search filters at its
own boundary so unsupported hits never reach the list. The display-face registry
becomes failure-tolerant: one unloadable face publishes the rest instead of
suppressing every re-render.

**Tech Stack:** React Native 0.86 / Expo SDK 57, TypeScript strict,
`expo-font` + `expo` (`reloadAppAsync`), `I18nManager`, zustand + AsyncStorage,
the repo's `check-*.mjs` scripts in place of a test runner.

**Spec:** N/A — the five v0.6.0-rc.2 bug reports and the read-only
investigation in **[Findings](#findings)** below are the spec. Each task cites
the finding it closes.

  `src/i18n/rtl-direction.ts` (new) and `src/theme/icon-sets.ts` (existing) fall

  `import type`**; `src/i18n/strings.ts` declares **no imports at all**.

  when behaviour changes: fonts → `docs/editor-font-loading.md` (its §6 "what

  doc and code disagree, fix the code.
- All user-facing copy lives in `src/i18n/strings.ts`, both `ar` and `en`; no
  inline literals in components.
- Follow `DESIGN.md`: 44 dp touch floor, `radius`/`spacing`/`typeScale` tokens,
  no floating chrome in the editor.
- **No version bump** in this plan. `chore(release)` owns `package.json` /
  `app.json`; this plan only records the fixes in `CHANGELOG.md`.
- Weigh web where it is cheap, but native (Android) is the bug report's
  platform. `adjustsFontSizeToFit` is Android/iOS-only — react-native-web ignores
  it, so on web the fallback must degrade to an ellipsis, never a clip.
